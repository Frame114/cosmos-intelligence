# Engineering Assessment

The project is assessed on demonstrated engineering competence, not the number of files or features.

| Category | Weight | Evidence expected |
|---|---:|---|
| Technical understanding | 20 | Can explain protocols, architecture, trade-offs and failure modes |
| Implementation quality | 25 | Correct, typed, maintainable and modular code |
| Code quality | 15 | Clear abstractions, style, naming and review discipline |
| Problem-solving | 15 | Diagnoses real failures and justifies decisions |
| Security and reliability | 15 | Safe configuration, validation, resilience and threat awareness |
| Documentation | 10 | Reproducible setup, architecture, decisions and operational guidance |
| **Total** | **100** | |

## Progression gates

- **Below 60:** revisit fundamentals and correct core design issues.
- **60–79:** continue with targeted improvements and supervised exercises.
- **80–89:** progress to the next major engineering phase.
- **90–100:** portfolio-quality evidence for the assessed scope.

A high score requires working code, passing tests, clear evidence and an ability to explain the implementation independently.
