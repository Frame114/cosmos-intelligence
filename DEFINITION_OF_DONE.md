# Definition of Done

**Version:** 1.0  
**Last updated:** 2026-11-13  
**Status:** Governing project checklist

A feature or milestone is done only when all applicable items are met and evidence is recorded.

- Requirements and acceptance criteria are linked to the implementation.
- Current official upstream/technology contracts were checked where applicable.
- Code follows documented boundaries, typing, configuration, error, security, provenance, and accessibility rules.
- Automated unit, contract, integration, API, frontend, MCP, security, and/or E2E tests were added for the behavior and relevant failure cases.
- Tests, lint, type checks, migration checks, and build commands actually ran and pass; results are recorded.
- NASA values retain units, provenance, and retrieval time; AI output is generated-labeled and citations validate.
- No hard-coded secrets; secret scanning and redaction behavior are checked.
- Docker Compose works for the feature; production port/network/health/volume behavior is correct.
- Documentation, OpenAPI, migrations, fixtures, README, changelog, decisions, status, roadmap, and technical debt are updated as applicable.
- Known limitations, residual risk, and evidence are recorded.
- Destructive operations, production deployments, and public releases have required human approval.
