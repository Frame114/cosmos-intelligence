# API Provenance

**Version:** 1.0  
**Last updated:** 2026-11-13  
**Status:** Phase 1 specification baseline  
**Purpose:** Specify how a displayed or generated claim can be traced to an upstream record.  
**Scope:** Covers the proposed API Provenance behavior and interfaces; current implementation status is tracked separately.  
**Assumptions:** This is a design baseline; verify repository state and mutable upstream contracts before implementation.  


## Required provenance

Every stored science record stores source code, canonical upstream identifier, source URL or documented lookup URL, retrieved_at UTC timestamp, source update/publication time when supplied, SHA-256 of exact response-item bytes or canonicalized JSON, source schema version, normalizer version, and a link to its raw source_record. Exact byte hash is preferred when response bytes can be associated safely with one item; otherwise document canonical JSON serialization so recomputations are stable.

## API/UI exposure

Public DTOs expose source label, source record ID, safe source URL, retrieved_at, and source-updated time when present. They expose normalized data by default, not full raw JSON. Detail pages may show a collapsible source metadata view with a size cap and safe field allowlist. API request logs store no query secrets/body.

## AI citations

Retriever returns evidence IDs and the exact version/hash used. The model can only return citation IDs from that set. A deterministic validator removes/rejects unknown IDs and checks citations against the stored record. Persist evidence IDs, source record IDs, record hashes, retrieval time, prompt version, model identifier, and final output hash with each report.

NASA’s currently published AI/SI media guidance creates ambiguity around direct NASA attribution in generated output. The interface should label the answer as generated by Cosmos and render a separate list of retrieved source records, avoiding wording that attributes generated prose to NASA, pending legal/policy review. Enabling public NASA-derived generative output remains blocked on that review.

## Evidence retention

Normalized source facts and provenance hashes are retained under the database retention policy. Raw JSON is retained for 24 months, then may be purged while retaining the record identity, source URL, hashes, retrieval timestamps, normalized data, and schema/normalizer versions. User report evidence records point to a stable source_record ID and stored hash, making deletion/retention behavior auditable.
